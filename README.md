# heatcalc · 工业热源计算助手

当前版本：**v0.1.0**，首个功能版本，版本日期 **2026-10-19**。

heatcalc 用于计算工业蒸汽供热场景中的设备功率、耗电量、购电成本和熔盐储量。项目提供网页对话界面，由大模型理解工况、调用 Python 计算工具，再用中文说明结果。目前支持电加热器和热泵两类热源。

| 模块 | 可以做什么 |
| --- | --- |
| 电加热器 | 根据蒸汽需求计算功率、电量和电费，或根据电费预算反算蒸汽流量 |
| 热泵 | 区分供汽时长与谷电充热时长，根据余热温度对应的 COP 完成正反算 |
| 熔盐储热 | 根据充热功率、时长、比热容和温差计算所需熔盐吨数 |
| 对话 Agent | 理解中文工况，调用计算工具，组织带单位的中文结果 |
| Vue 网页 | 管理多个对话，支持命名、删除、Markdown 回复和请求状态显示 |
| FastAPI 后端 | 提供健康检查、对话接口和交互式接口文档 |

项目目前是**本机开发与计算验证版本**，不是已经完成工程设备选型或生产部署的系统。计算功能和当前限制分别见第 1、2、9 节。

## 1. 项目功能

### 电加热器成本与蒸汽流量

根据蒸汽、给水工况，蒸汽质量流量、供汽时长、谷电充热时长、电价和设备效率，完成以下计算：

```text
蒸汽需求 → 制汽热功率 → SGS 入口热功率 → 供汽时段所需热功率
  → 总需热量 → 谷电时段所需充热功率 → 输入电功率 → 耗电量 → 购电成本
```

SGS 表示蒸汽发生系统。换热效率、储热效率和电热效率分别用于对应环节。也可以根据指定购电成本，依次计算耗电量、总供热量，再按供汽时长得到可供蒸汽质量流量。

水和蒸汽的比焓通过 `iapws.IAPWS95` 根据压力、温度计算。正反算复用同一套物性与效率关系，可使用相同工况进行往返校验。

### 热泵正算与反算

热泵使用供热 COP 将热功率和输入电功率关联起来。每次计算先查一次 COP，后续功率换算和返回结果复用这个值。当前按余热温度查表：

| 余热温度 | 供热 COP |
| --- | --- |
| 30 °C | 1.3 |

目前只配置了上述数据点。其他温度会报错，需要在 `src/heatcalc/pump_heater.py` 的 `COP_TABLE` 中补充数据，当前没有自动插值或外推。

热泵分别接收两个时长：

| 参数 | 含义 | 作用 |
| --- | --- | --- |
| `steam_supply_hours` | 供汽时长，h | 根据蒸汽需求功率计算总需热量 |
| `operating_hours` | 谷电充热时长，h | 根据总需热量计算谷电期间的设备功率 |

例如供汽 24 小时、谷电充热 8 小时，需要在 8 小时内提供满足 24 小时供汽需求的热量。正算先求总需热量，再按谷电时长计算功率和电费；反算根据电费得到可用热量，再按供汽时长计算蒸汽流量。两个时长均须大于零。

电加热器和热泵均要求分别提供这两个时长，策略函数和 Agent 工具中的 `steam_supply_hours` 均为必填参数，两个时长都必须是大于零的有限数值。供汽时长决定总需热量，谷电充热时长决定所需设备功率。

### 熔盐储量

根据充热功率、储热时长、熔盐比热容和高低温差，计算所需熔盐质量，单位为吨。该工具可以单独调用，也可以使用热源正反算返回的 `charging_power` 继续计算。

`storage_duration` 必须与传入的功率相对应。使用电加热器或热泵结果中谷电期间的 `charging_power` 时，若要覆盖该次充热的全部热量，应使用相同的谷电充热时长。例如功率对应 8 小时充热，就传入 8 小时，不能再乘 24 小时供汽时长。

### 网页对话

- 新建、切换、命名和删除多个对话。
- 默认用首次提问生成标题；点击侧栏“命名”可自定义名称，首次提问不会覆盖自定义名称。
- 编辑名称时，Enter 或移开焦点保存，Esc 取消；空名称不覆盖原名称。
- 删除当前对话后选择相邻对话，删除最后一个后自动创建空对话。
- 回复、错误提示和加载状态始终属于发起请求的对话，切换或新建后不会串消息。
- 不同对话可以分别等待回复，同一对话等待期间阻止重复提交。
- 删除等待回复的对话时，前端取消请求，并忽略迟到的回复。
- 支持普通 Markdown 展示，默认要求计算结果保留两位小数。

**当前对话、名称和消息仅保存在页面内存中，刷新页面后会清空。** 尚未接入数据库、浏览器持久化或用户账户。

## 2. 计算逻辑与单位

### 工具输入与展示单位

| 量 | Python 工具单位 | 网页常用展示单位 |
| --- | --- | --- |
| 蒸汽、给水压力 | MPa | MPa |
| 温度 | °C | °C |
| 制汽比焓差 | kJ/kg | kJ/kg |
| 蒸汽质量流量 | kg/s | t/h |
| 热功率 / 电功率 | kW | MWt / MWe |
| 热量 / 耗电量 | kWh | MWht / MWhe |
| 时长 | h | h |
| 电价 | 元/kWh | 元/kWh |
| 购电成本 | 元 | 元 |
| 熔盐比热容 | kJ/(kg·K) | kJ/(kg·K) |
| 熔盐质量 | 吨 | t |
| COP、效率 | 无量纲 | 无量纲 |

```text
质量流量 (t/h) = 质量流量 (kg/s) × 3.6
质量流量 (kg/s) = 质量流量 (t/h) ÷ 3.6
功率 (MW) = 功率 (kW) ÷ 1000
能量 (MWh) = 能量 (kWh) ÷ 1000
```

计算保留原始精度。`agent/formatting.py` 统一处理单位换算和舍入；`agent_core.py` 向模型提供展示规则，要求最终文本补齐两位小数。继续调用工具时使用未舍入的原始值。

### 电加热器公式

```text
制汽比焓差 = 蒸汽比焓 - 给水比焓
制汽热功率 = 蒸汽质量流量 × 制汽比焓差
SGS 入口热功率 = 制汽热功率 ÷ 换热效率
供汽时段所需热功率 = SGS 入口热功率 ÷ 储热效率
总供热量 = 供汽时段所需热功率 × 供汽时长
所需充热功率 = 总供热量 ÷ 谷电充热时长
输入电功率 = 所需充热功率 ÷ 电热效率
耗电量 = 输入电功率 × 谷电充热时长
购电成本 = 耗电量 × 电价
```

上述功率为 kW，质量流量为 kg/s，时长为 h，能量为 kWh。

根据电费计算蒸汽流量时，先用电费除以电价得到耗电量，再乘电热效率得到总供热量；总供热量除以供汽时长后，依次考虑储热、换热损失并除以制汽比焓差，得到蒸汽质量流量。

### 热泵公式

```text
制汽热功率 = 蒸汽质量流量 × 制汽比焓差
SGS 入口热功率 = 制汽热功率 ÷ 换热效率
供汽时段所需热功率 = SGS 入口热功率 ÷ 储热效率
总供热量 = 供汽时段所需热功率 × 供汽时长
热泵实际充热功率 = 总供热量 ÷ 谷电充热时长
输入电功率 = 热泵实际充热功率 ÷ COP
耗电量 = 输入电功率 × 谷电充热时长
购电成本 = 耗电量 × 电价
```

功率乘时长得到的是热量或电量。当前固定 COP、固定效率模型中，同一蒸汽需求和供汽时长下，缩短谷电时长会提高所需设备功率，总耗电量不变。

热泵反算：

```text
耗电量 = 购电成本 ÷ 电价
输入电功率 = 耗电量 ÷ 谷电充热时长
实际充热功率 = 输入电功率 × COP
总供热量 = 实际充热功率 × 谷电充热时长
供汽时段所需热功率 = 总供热量 ÷ 供汽时长
SGS 入口热功率 = 供汽时段所需热功率 × 储热效率
制汽热功率 = SGS 入口热功率 × 换热效率
蒸汽质量流量 = 制汽热功率 ÷ 制汽比焓差
```

### 储盐公式

```text
储热量 (kJ) = 充热功率 (kW) × 储热时长 (h) × 3600
每千克熔盐可储热量 (kJ/kg) = 比热容 × 高低温差
熔盐质量 (吨) = 储热量 ÷ 每千克熔盐可储热量 ÷ 1000
```

例如 1000 kW 充热 8 小时，比热容 1.5 kJ/(kg·K)，高低温差 240 K，所需熔盐为 **80.00 吨**。

```text
│   │   └── main.py                  # 早期终端入口
│   └── backend/
│       ├── main.py                  # FastAPI 应用和健康检查
│       └── routers/chat.py          # 对话 API
├── tests/                           # Python 计算和工具测试
└── frontend/
    ├── src/App.vue                  # 页面组装
    ├── src/composables/             # 对话、命名、删除和请求状态
    ├── src/components/              # 侧栏、消息和输入框
    └── tests/                       # 对话回归测试
```

```text
Vue 网页 → POST /api/chat → Agent → 工具 → 热源策略 / 储盐函数
                                      ↓
                      原始结果 + 单位换算后的展示结果 → 中文回复
```

基类约定统一的正反算接口，提供蒸汽物性和共用计算；各设备定义功率换算方式。工具层负责参数说明与调用，业务计算集中在策略和公共计算模块。

## 4. 首次安装

### 环境要求

- Python **3.13**，与 `.python-version` 对齐；项目声明支持 3.13 及以上。
- [uv](https://docs.astral.sh/uv/)：管理 Python 依赖。
- Node.js **24 LTS** 和 npm：构建前端及直接运行 TypeScript 测试。
- 支持工具调用的 OpenAI 兼容模型服务及有效 API Key。

### 下载代码并安装依赖

```bash
git clone https://github.com/ASULEL/heatcalc.git
cd heatcalc
uv sync --locked
```

安装前端依赖：

```bash
cd frontend
npm ci
cd ..
```

`uv sync` 会在根目录创建 `.venv`。后续命令直接使用该环境，无需先手动激活。

### 配置模型接口

在项目根目录执行；已有 `.env` 时不要覆盖原来的密钥配置：

```bash
if [ ! -f .env ]; then
  cp .env.example .env
fi
```

编辑 `.env`：

```dotenv
API_KEY=替换为你的接口密钥
API_BASE_URL=https://api.deepseek.com
```

`API_BASE_URL` 填实际服务商提供的 OpenAI 兼容接口地址，模板中的 DeepSeek 地址可按所用服务替换。

当前网页 Agent 在 `src/heatcalc/agent/agent_core.py` 中使用模型名 `deepseek-v4.1-flash`。如果接口提供的模型名称不同，需要修改该文件中的 `model`。早期终端入口 `agent/main.py` 单独配置了模型；使用该入口时也需同步调整。

`.env` 不提交到 Git，仓库仅提供占位配置模板 `.env.example`。修改接口配置后重启后端。

## 6. 使用示例

### 电加热器购电成本

```text
用电加热器供汽。蒸汽压力 1.5 MPa、温度 200°C；给水压力 0.1 MPa、
温度 20°C；蒸汽流量 100 t/h；供汽 8 小时，谷电充热 8 小时；电价 0.35 元/kWh；
电热效率 0.985，换热效率 0.99，储热效率 0.99；
熔盐比热容 1.5 kJ/(kg·K)，最高温度 540°C，最低温度 300°C。
请计算各阶段功率、耗电量和购电成本。
```

相同参数下，Python 算法的购电成本约为 **218491.75 元**。

如果改为供汽 24 小时、谷电充热仍为 8 小时，则所需充热功率约 **230.59 MWt**、输入电功率约 **234.10 MWe**，购电成本约 **655475.26 元**。用同一工况和这笔未舍入的购电成本计算蒸汽流量，结果仍为 **100.00 t/h**。

### 热泵正算

```text
用热泵供汽。蒸汽压力 1.5 MPa、温度 200°C；给水压力 0.1 MPa、
温度 20°C；蒸汽流量 100 t/h；供汽 24 小时，谷电充热 8 小时；
余热温度 30°C；电价 0.35 元/kWh；换热效率 0.99，储热效率 0.99；
熔盐比热容 1.5 kJ/(kg·K)，最高温度 540°C，最低温度 300°C。
请计算热泵热功率、电功率、耗电量和购电成本。
```

相同参数及当前 COP 1.3 下，输入电功率约 **177.37 MWe**，购电成本约 **496648.57 元**。此示例与电加热器示例的供汽时长不同，不能直接用总费用比较设备经济性。

### 热泵反算流量

```text
热泵购电预算 2800 元，电价 0.35 元/kWh，谷电充热 8 小时，供汽 24 小时。
余热温度 30°C，换热效率 0.99，储热效率 0.99。
蒸汽压力 1.5 MPa、温度 200°C；给水压力 0.1 MPa、温度 20°C。
熔盐比热容 1.5 kJ/(kg·K)，最高温度 540°C，最低温度 300°C。
请反算蒸汽质量流量，并以 t/h 展示。
```

对应蒸汽流量约为 **0.56 t/h**，指 24 小时供汽期间的流量。

### 单独计算储盐

```text
充热功率 1 MW，储热时长 8 小时，熔盐比热容 1.5 kJ/(kg·K)，
最高温度 540°C，最低温度 300°C，请计算所需熔盐储量。
```

结果为 **80.00 吨**。

## 7. API

### GET `/api/health`

检查后端是否启动，不调用模型：

```bash
curl http://127.0.0.1:8000/api/health
```

### POST `/api/chat`

请求体示例：

```json
{
  "message": "请计算这组工况的购电成本",
  "history": [
    {"role": "user", "content": "之前给出的工况参数"},
    {"role": "assistant", "content": "上一条回复"}
  ]
}
```

`history` 不包含本次 `message`，新对话传入空列表。后端转换历史消息并调用 Agent，返回：

```json
{"response": "模型生成的中文回复"}
```

目前一次返回完整文本，没有流式输出。对话 ID、标题、切换和删除由前端管理，后端不持久化对话。

## 9. 常见问题与当前限制

### `Address already in use` / `[Errno 48]`

8000 端口已被占用。macOS 中可查看监听进程：

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

如果原后端正常运行，可以直接使用；需要重启时，回到启动它的终端按 `Ctrl+C`，再执行启动命令。

### 前端能打开，但提问失败

依次检查后端健康接口、`.env` 中的地址与密钥、服务商是否提供配置的模型及工具调用能力，具体错误通常在后端终端显示。如果报找不到模型，修改 `agent_core.py` 中的 `model` 并重启后端；当前模型名未通过环境变量配置。

### 不配置 API Key 能否使用计算函数

可以。热源策略与储盐函数是独立 Python 模块，模型配置只用于对话式调用。Python 算法测试不需要真实 API Key。

### Markdown 能显示，但公式仍是原始字符

当前使用 `marked` 渲染普通 Markdown，尚未接入 KaTeX 或 MathJax。`\frac`、`\[...\]`、`$$...$$` 等语法尚不能直接渲染为数学公式。

### 刷新后对话消失

当前只在页面内存中保存对话，尚未实现持久化。对话命名不会改变保存方式。

### 计算模型范围

当前采用固定工况、效率和 COP 查表。尚未包含设备额定功率约束、选型、COP 随负荷变化、分时调度优化、投资回收期或动态储热仿真。

### 本机使用与安全边界

- 当前没有登录认证、权限控制、限流或 HTTPS 部署配置，不应直接暴露到公网。
- 网页会将本次提问和所属对话的历史发送给后端，再由后端调用配置的模型服务。不要提交不允许发送给该服务的敏感工况或其他机密信息。
- 网页的 Markdown 渲染尚未加入专门的 HTML 净化层，不要将未经信任的回复作为安全内容发布给其他用户。
- 模型服务可能按调用量收费；刷新网页不会撤回已发给模型服务的请求，删除对话也不保证停止后端已开始的计算或模型调用。
- 计算结果用于当前算法的验证和方案初步比较；实际工程设计仍需结合设备资料、工况边界和专业校核。
