# heatcalc 网页前端

使用 Vue 3、TypeScript、Vite 和 Tailwind CSS，当前版本为 **v0.1.0**。完整功能、计算逻辑及后端启动流程见[根目录 README](../README.md)。

代码与文档核对日期：2026-10-26。当前框架问题与后续讨论顺序见[架构审查与改进清单](../docs/架构审查与改进清单.md)。

## 安装与启动

推荐 Node.js 24 LTS。在此目录执行：

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

打开 <http://127.0.0.1:5173/>。同时需要按根目录 README 启动 8000 端口的 Python 后端并配置模型接口。

前端当前直接请求 `http://127.0.0.1:8000/api/chat`，不会经过已配置的 Vite `/api` 代理；只启动 Vue 无法完成聊天。`--strictPort` 让 5173 被占用时直接报错，避免自动换端口后与后端允许的跨域地址不一致。

## 对话操作

- 点击“新建对话”创建，点击标题切换。
- 鼠标移到侧栏对话上，点击“⋯”编辑标题，Enter 或移开焦点保存，Esc 取消；空名称不覆盖原名称。
- 点击对话旁的“×”移除对话，删除最后一个后自动创建空对话。
- 请求中的回复属于发起请求的对话，切换后不会串消息。
- 对话暂存在页面内存中，刷新后清空。
- 首页提供 5 个常用场景和可展开的 8 项计算工具列表；经济测算进入方案流程，其他入口发送计算目标，由模型决定如何补参和调用。
- 顶部按钮可切换明暗主题，主题状态同样不持久化。

## 参数表

- 模型请求参数表后，按中文标签、单位和业务分组展示；详细设备参数默认折叠。
- 后端各 Tool 在自己的文件中定义输入模型，表单统一读取模型中的中文说明、单位、分组及示例值。
- 已知参数可以回填；单独 COP 工具还会预填部分标有“Excel示例”的参数，用户可修改后提交，空白项不会自动补齐。
- COP 相关表单的三个主循环压力显示 MPa，提交时乘以 1000 转为 kPa；独立 COP 输出热功率显示 MWt，提交时转为 kW。各段压降仍为 kPa。
- 循环介质下拉目前仅有 `air`，后端函数支持的介质范围更广。
- 热源表单提交时发送中文参数摘要及 `parameter_values`，服务端将参数转入模型上下文。
- 经济测算的借款、成本、收入税金、所得税及现金流表单来自各自输入模型；五步共用 `POST /api/tools/calculate_economic_scheme`。
- 表单 `required` 目前用于提示，尚未形成完整的必填、数值范围和工况关系校验；经济测算表单成功提交后只读，失败仍可重试。
- 压缩机实际进口压力已按回热器低压侧出口减去连接管道压降计算，表单中的原进口压力仍为兼容字段，不能独立覆盖推导结果。

## 当前界面边界

顶部“方案”支持选择经济测算、查看进度与结果、继续填写；“档案”仍是占位按钮；“模型服务已连接”是固定显示，尚无真实连通检测。“默认用户”是占位名称，未接入账户系统。普通 Markdown、借款、成本和收入税金表格已支持，数学公式、流式回复和计算报告尚未实现。

## 经济测算方案

点击顶部“方案”→“新建经济测算”会先创建一个新对话，再开始借款参数填写；也可以选择可调用工具中的“经济测算”，在当前对话中开始。对话提出借款表或成本表需求时，模型也会进入同一方案流程。

1. 先填写9个借款参数，生成借款还本付息表。示例为第1年提款80%、第2年提款剩余贷款，均可修改。
2. 生成借款表后，在新消息填写成本参数：运营年数、折旧年限、建设期抵扣比例、可折旧比例、保险费率与除税系数、维修比例区间与各年费用。默认值取自当前 Excel 案例，输入框聚焦后可直接键入替换。
3. 成本表自动引用本方案的借款年份、建设期利息和运营期当年利息。界面保留经营成本、折旧摊销、财务成本的分组表头。
4. 成本完成后填写收入及税金参数：含税/不含税口径、运营年数、除税率、销项与购电进项税率、建设期抵扣比例、附加税系数，以及年度蒸汽收入和碳收益。蒸汽量可留空，金额可批量应用到运营年份。
5. 收入税金表显示不含税收入分项、同年购电进项税、建设期抵扣年初余额与剩余额度、实缴增值税、城建及教育附加。税率以百分数显示，提交时转换为小数。
6. 收入税金完成后填写所得税率（默认 25%），生成所得税表。表格列示营业收入、附加税、总成本、利润总额、本年亏损、累计亏损、弥补亏损、应纳税所得额、所得税和净利润；亏损结转到以后年度盈利时先弥补。
7. 所得税完成后填写资本金比例（默认 30%），一次生成资本金和全投资两张现金流量表。表格列示营业收入、回收固定资产余值、建设投资、借款本金偿还、借款利息、经营成本、附加税、所得税、净现金流量、累计净现金流量和静态投资回收期，并给出 IRR。

两张现金流表在运营结束后只保留年份和阶段，各金额及累计值留空。逐年预计回收期恢复原 Excel K 列的含义，首次回本后停止列示；汇总回收期只取首次实际回本结果。固定资产余值按截至期末的剩余账面价值估算，只在最后运营年回收一次。

方案完成后，对话中两张现金流量表下方和方案页均提供“导出 Excel”，下载该方案最新的全部测算表格。前端把当前方案的五步原始结果提交到 `POST /api/tools/calculate_economic_scheme/export`，下载包含借款、成本、收入及税金、所得税、两张现金流量表和测算说明的公式版工作簿。黄色单元格可修改，跨表引用和小计为公式，同时保存计算结果缓存；打开可直接读取，修改输入后自动重算。请求期间显示“正在导出”，失败在按钮下方提示；下载链接由浏览器接管后再释放。

五步共用 `POST /api/tools/calculate_economic_scheme`，分别发送 `request.step = 'loan'`、`'cost'`、`'revenue_tax'`、`'income_tax'`、`'cash_flow'`。成本步骤传递本条消息绑定的 `scheme_id` 与 `loan_result`，税金步骤再传递同一方案的 `cost_result`，所得税步骤再传递同一方案的 `revenue_tax_result`，现金流步骤再传递同一方案的 `income_tax_result`。来源与输入快照保存在消息中。

`conversation.scenario.economicSchemes` 保存各方案的进度和原始六张表；`calculationResults` 保存每个方案的最新结果供后续对话引用，请求中附带页面显示的方案名称。金额展示四位小数，IRR 和回收期展示两位小数，存储原始精度。

```ts
const scheme = conversation.scenario.economicSchemes[0]!
const annualInterest = scheme.loanResult!.schedule.map(row => row.interest_expense)
const totalCosts = scheme.costResult!.schedule.map(row => row.total_cost)
const vatPaid = scheme.revenueTaxResult!.schedule.map(row => row.vat_paid)
const incomeTax = scheme.incomeTaxResult!.schedule.map(row => row.income_tax)
const capitalIrr = scheme.cashFlowResult!.capital.summary.irr
const totalIrr = scheme.cashFlowResult!.total_investment.summary.irr
```

历史消息保存自己的来源与提交参数，成功后表单只读；新的方案和计算结果不会改变旧表单的来源或内容。顶部方案页可以查看当前对话内所有经济测算，继续未完成步骤或查看六张表。

在对话中发送“将静态投资改成32000”可修改已有方案。借款及已生成的后续表格联动重算；未提交的旧表单显示“参数已更新，请使用最新表单”并停止提交，新的表单绑定修改后的来源。模型超时会显示具体原因并结束等待，可以重新发送请求。

方案数据目前只在页面内存中，刷新后清空。

## 验证与构建

```bash
npm test
npm run build
```

前端测试使用 Node.js 内置测试运行器，模拟响应验证对话、表单提交、单位倍率及方案数据隔离，并通过 Vue 服务端渲染验证借款表格。不调用模型，也不执行完整浏览器交互测试。构建包含 TypeScript 检查，产物输出到 `dist/`。
